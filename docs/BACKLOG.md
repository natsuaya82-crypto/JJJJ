| 誕生日 | 倍率 | 下落 |
|---|---|---|
| 22→23歳 | 5→4 | −20% |

| | 旧 | 新 |
|---|---|---|
| 1年での最大の下落 | **−33%**（31→32歳） | **−10%**（33→34歳） |
| 全5,800人の移籍金の合計 | 7,002億 | 7,007億（**+0.1%**） |

### 調べたこと：オフとシーズン中の分かれ方

「オフシーズン／オンシーズンという考えが無い、いつでも移籍していいはず」というご指摘を受けて、
どこで何が動いているかを数えました。**移籍ウィンドウは撤廃済みで、いつでも移籍できます。**
ただし処理の置き場所が分かれていました。

| いつ | 何が動くか |
|---|---|
| **シーズン中（毎レース）** | 売り出し・買い取り打診・直訴／入札の決着／CPU移籍の決着／FA獲得／海外オファー／レンタル／トレード打診／日本↔海外・海外↔海外 |
| **シーズンの切れ目（ドラフト）** | 解雇 → **CPU間移籍** → **CPU間トレード** → **CPU間レンタル** → FA補強 |
| **`endSeason`** | 引退・契約満了・格の更新・海外リーグの1年 |

つまり**シーズン中に無いのは「CPU同士の移籍・トレード・レンタル」の3つだけ**でした。
プレイヤーが絡む移籍は全部いつでも起きるのに、CPU同士だけがオフに固まっている非対称な形です。

`済`（2026-08-11・オーナー判断「C：シーズン中にも動かす」「頻度は3週に1回くらい」）：
**同じ関数を件数だけ絞ってシーズン中にも回します**（`runCpuMarketTick`）。別実装は作りません。

**回数はレースの本数ではなく日付で数えます。** 部ごとにレース数が違うためです。

| 部 | レース | ＋記録会 | 間隔の中央値 | いちばん空くところ |
|---|---|---|---|---|
| 1部 | 10戦 | 17コマ | 21日 | 28日 |
| 2部 | 8戦 | 15コマ | 21日 | **42日** |
| 3部 | 7戦 | 14コマ | 21日 | **49日** |

コマのたびに回すと 17／15／14 回と差が出て、3部には49日も市場が止まる区間ができます。
**日程に日付が振ってあるのは本数が違っても1年の長さを揃えるため**なので、市場も日付で数えます
（`cpuMarketRounds`：最後に回した基準日から21日ごと。**基準日は21日ずつ進める**——
その日の日付にリセットすると端数が毎回捨てられて部ごとに差が残る）。

`CPU_TICK_TRANSFERS`(3)／`CPU_TICK_TRADES`(1)／`CPU_TICK_LOANS`(1) の3つ。

**トレードが0件のままなのは変わりません。**

### 訂正（2026-08-11）：「条件が論理的に噛み合わない」は言い過ぎでした

人数の門を外して数え直したところ、51,000通りのうち**1,224通り**が両方の条件を満たします。
「同時に立たない」のではなく「レアだが立つ」でした。上の証明は撤回します。

**本当の詰まりは人数の門でした。**

    解雇   … 1軍登録上限23人の超過ぶんを切る  → 51クラブ全部がちょうど23人
    トレード … 買い手は「23人未満」でないと参加できない → 買い手 0クラブ

しかも**1対1の交換は人数が変わりません**。この門はトレードには要らないものです。
実際に動いていた12クラブは「その前の移籍で人が抜けて22人になったクラブ」だけでした。

残る壁は釣り合いで、こちらは正しい判定です（控えでレギュラーは買えない。
両条件を満たした1,224通りの「出す額÷もらう額」は中央値0.47、成立は0.92以上）。
つまり詰まりの本体は「条件が変」ではなく**出すものが弱すぎる**ことでした。

### A-10. 「余剰か」の線 … `済`（2026-08-12・オーナー判断「序列15番手以降だけでいいよ」）

`isSurplus` は3つの条件のうち1つでも満たせば余剰、という形でした。

    序列が「走れる人数の2倍」より下（15番手以降）
    または **名簿が SELL_ROSTER_CROWDED(21) 人より多い**   ← 全232クラブが23〜25人なので常に真
    または 今季干されている                                 ← seeksPlayingTime の中で序列を先に見るので上に含まれる

つまり **`isSurplus` は恒真**で、その先にある主力の引き抜き割増（`POACH_PREMIUM` 1.4倍）と
本人同意（`clubBlessed`）が**どの経路でも一度も発火していませんでした**。
序列だけにしたので、いまは効いています。

| | 恒真だったとき | 序列だけ |
|---|---|---|
| 国内CPU間 | 98件 / 151.1億 | 97件 / **201.7億** |
| 海外↔海外 | 20件 / 37.1億 | 20件 / **52.0億** |
| 海外→日本 | 4件 / 5.9億 | 4件 / **8.3億** |
| 日本→海外 | 6件 / 8.2億 | 6件 / **9.6億** |

**残った観察（決めることではない）：移籍金つきの移籍は、いま全部が割増です。**
国内97件・海外30件のうち、出す側で15番手以降だった選手は**0件**でした。
クラブが移籍金を払うのは「穴が埋まって、そこで走れる」選手だけなので、
15番手以降に買い手は現れません。余剰の選手は解雇→FA（0円）かレンタルで動きます。
実質「移籍金を払う移籍＝すべて1.4倍」という状態です。気になるようなら言ってください。

`scripts/check-offseason.ts` の [7] が、線そのもの（14番手＝主力／15番手＝余剰）と
「割増の枝が実際に発火しているか」を見張ります（恒真に戻すと落ちることを確認済み）。

drop table if exists public.rosters   cascade;
