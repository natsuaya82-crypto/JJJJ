## A. 仕様・バランス（オーナーが決めること）

### A-1. 移籍金が誕生日をまたいだ瞬間に落ちる

年齢倍率が段になっているので、**能力が1も変わっていないのに**誕生日で移籍金が下がります。

| 誕生日 | 倍率 | 下落 |
|---|---|---|
| 22→23歳 | 5→4 | −20% |
| 27→28歳 | 4→3 | −25% |
| 31→32歳 | 3→2 | −33% |

- どこ … `src/utils/playerUtils.ts` の `transferFeeAgeMultiplier`
- 現状 … CLAUDE.md に現行仕様として書いてあるとおりの動き。**壊れてはいない**
- 気になる点 … 「27歳の主力は28歳になる前に売る」が最適解になる。
  遊び方として意図どおりか
- 見つけ方 … 2026-08-11、点検の書き換え中に実測（数値は統括が再測して確認）

### A-2. 契約の年俸ダイヤルの上限

いまの上限は **交渉8,000万／ドラフト6,000万**（`src/data/economy.ts` の
`NEGOTIATION_SALARY_MAX` / `DRAFT_SALARY_MAX`）。
オーナーから「上限って1億くらいなかったっけ？」という発言があったが、実装は8,000万。
上げるかどうかは未決。

### A-3. 移籍金の入札で「競り負け」の起き方が変わっている

旧仕様「上回るクラブがいれば即 rejected」→ 現仕様「1回目は countered で上乗せの機会を出す」。
点検（`scripts/check-transfer-bid.ts`）は旧仕様のまま止めてある（B-1）。
**どちらが正なのかを決める必要がある。**

## B. 止めたままの点検

### B-1. `transfer-bid` … 12件（`pending: 12` で登録済み。これ以上増えたら落ちる）

`trade-value` と同じ**3種類の仕分けがまだ**。実際、12件の中には

- 仕様が変わったもの（A-3）
- **分解でコードが engine へ移っただけのもの**
  （`入札の判定は resolveBid を呼ぶだけ — 1箇所` ／ `移すのは movePlayer 1本` など）

が混ざっている。`trade-value` は同じ仕分けで 20件 → 0件になった。同じことをすれば減る。

### B-2. `continental` … 分布のゆらぎ（`~` 印）

大陸予選で「上位の通過率 ≦ 下位の通過率」になる世界が **40回に2回**ほど生成される。
テストの不備ではなく、生成された名簿しだいで国同士の強さの差が潰れる回がある。
判定は緩めていない。
