## 1. `teams` 引数は何に使われているか

**3つだけ**です。

1. `withMoney(teams, from, to, fee)` … 移籍金を動かす
2. `teams.find(t => t.id === dest)?.name` … 退団のお知らせに出す行き先名（`opts.toName` が無いときだけ）
3. 返り値 `nextTeams`

つまり **`teams: []` を渡す意味は「お金を動かさない／行き先名は自分で渡す」**です。
引数そのものが不要になっているわけではありません（国内クラブ同士の移籍金はここが唯一の経路）。

## 2. 見つかった問題（どちらも「お金」）

CLAUDE.md にはこう書いてあります。

> **海外クラブの資金も本物です。置き場所は `finance.budget` 1本**（国内チームとまったく同じ項目）。
> 買えば減り、売れば増え、毎年 `computeNextSeasonBudget` で精算されます。

**この決まりが守られているのは、オフシーズンの `simulateCrossBorderTransfers` の中だけ**でした。
海外クラブの `finance.budget` を書き換えている場所は、リポジトリ全体で

- `engine/foreignTransfers.ts`（オフの日本↔海外。`fBudget` を書き戻す）
- `engine/foreignSeason.ts`（年度末の精算）
- `store/persistence/normalizeSave.ts`（読み込み時の形の補正）

の3つしかありません。

### 2-1. 海外クラブ同士の引き抜きが「無料」

`simulateForeignTransferMarket`（`engine/foreignTransfers.ts` の前半）は、
選手を選ぶ条件が **「そのクラブに必要か」と「そこで走れるか」だけ**で、
**移籍金も予算も一切見ていません。** `movePlayer` にも `fee` を渡していません（`kind: 'free'`）。

- 起きること … 格20のクラブが格1のクラブから、0円でエースを引き抜ける
- 対して、日本↔海外（同じファイルの後半）は `fBudget[c.id] < fee` で買えるかを見ている

**同じファイルの中で、お金の扱いが前半と後半で違います。**

### 2-2. シーズン中の日本↔海外の売買で、海外側の予算が動かない

自チームに届く買い取り打診は海外クラブからも来ます（`offer.fromForeign`）。
承諾すると `movePlayer` が移籍金を動かしますが、`teams` に居るのは国内クラブだけなので

- **売る** … 自チームの資金は増える。**海外クラブの資金は減らない**（お金が湧く）
- **買う** … 自チームの資金は減る。**海外クラブの資金は増えない**（お金が消える）

`movePlayer` のコメントは「片側だけ動くのが正しい」と書いていますが、
それが正しいのは**海外側を別の場所で精算している場合**だけです。
オフの `simulateCrossBorderTransfers` はそうしています（`fBudget` を書き戻す）が、
**シーズン中の経路には、それに当たる処理がありません。**

- 影響 … 海外クラブは、シーズン中にいくら買っても資金が減らない。
  CLAUDE.md が「一度直した」と書いている
  「海外だけ使っても減らない別のお金で動いている」状態が、シーズン中には残っている

## 3. 問題なしと確認したもの

### 3-1. 移籍金の二重計上は起きていない

`simulateCrossBorderTransfers` は自前で `budget`（国内）と `fBudget`（海外）の表を持ち、
そのあと `movePlayer` にも `fee` を渡しています。一見すると二重ですが、

- `budget`（国内）… **買えるかどうかの判定にしか使わない。書き戻していない**
- `fBudget`（海外）… 書き戻す（国内クラブは `teams` に居るので `movePlayer` が動かす）

と役割が分かれていて、どちらの側も**1回だけ**動きます。

### 3-2. 退団のお知らせが2系統あるが、重ならない

| 系統 | いつ | どうやって |
|---|---|---|
| `movePlayer` の `notice` | シーズン中 | 移動のたびに1件作る（`myTeamId` を渡した18箇所） |
| `engine/departureNotices` | オフシーズン | 「シーズン頭に居た選手」と「整理後」を突き合わせる |

オフシーズンの `movePlayer` 呼び出しは `myTeamId` を渡していないので、
同じ退団が2件出ることはありません。**ただし片方に `myTeamId` を足すと二重になります。**
（この危うさは残っているので、触るときは注意）

### 3-3. 責務の線引きは、すでにファイルの先頭に書いてある

`movePlayer` がやること・やらないことはヘッダに明記されていて、実装とも一致していました。

- やる … 所属・移籍金・加入年/節・レンタル・札はがし・調子リセット・禁止期限・契約・履歴・退団通知・引退
- やらない … ニュースの文面、引退選手のデータ削り

**呼び出し元が別途やる必要があるのは、この「やらない」2つだけ**です（＋2-2 の海外側の精算）。
